# Coverage

## Inspection sequence

Adapt depth to the subject. Do not skip the start.

1. Read the catalog or landing surface as a newcomer.
2. Enumerate every in-scope project or included page.
3. Read each card or primary description completely.
4. Follow the primary public destination.
5. Inspect a relevant example, artifact, or first-use route.
6. Verify consequential or doubtful claims with a suitable source.
7. Inspect actual UI where an aesthetic judgment needs it.
8. Record gaps and stop once the evidence is enough.

Expand tabs, accordions, and client-rendered panels. Do not mistake
a text extractor's first paint for the whole catalog.

## Coverage values

Use `inspected`, `partially inspected`, `not inspected`, `blocked`,
or `not applicable`.

A README is evidence of documented behavior, not proof the
implementation performs it. A screenshot supports appearance, not
a backend guarantee.

A page-fetch error or missing connector is an access limitation
until independently established otherwise. Do not report a broken
site or lower a score only because this environment could not
retrieve it.

## Visual notes

Prefer a desktop viewport near 1440×900 and a narrow viewport near
390×844 when the environment supports them. Record the actual size.
Inspect settled UI. Do not score a transient blank frame.

Never invent an aesthetic score for an uninspected interface.

## Default review boundary

Default mode is a presentation and product-concept review. It does
not automatically include a full source audit, penetration test,
benchmark campaign, or verification of every platform.
